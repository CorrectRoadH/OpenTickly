As notas de versão ficam no GitHub Releases. Esta página explica como as versões são lançadas e como atualizar.

- Versões atuais e anteriores: [github.com/CorrectRoadH/OpenTickly/releases](https://github.com/CorrectRoadH/OpenTickly/releases)
- Histórico completo de commits: [github.com/CorrectRoadH/OpenTickly/commits/main](https://github.com/CorrectRoadH/OpenTickly/commits/main)
- Imagens Docker: [hub.docker.com/r/correctroad/opentickly](https://hub.docker.com/r/correctroad/opentickly)

## Como as versões são lançadas

Cada versão é uma tag do git em `main`. Ao criar a tag, uma nova imagem Docker é publicada automaticamente e a demo em [track.opentoggl.com](https://track.opentoggl.com) é atualizada. Para atualizar uma instância auto-hospedada, rode `docker compose pull && docker compose up -d`.

## Notas de atualização

Normalmente é só atualizar, sem fazer mais nada. O banco de dados é atualizado automaticamente quando o servidor inicia, e a API compatível com o Toggl não muda, então suas integrações continuam funcionando.

Se uma versão precisar de passos extras, a GitHub Release dela traz uma seção **Upgrade** explicando o que fazer. Se não houver essa seção, é uma atualização normal.

Se uma atualização falhar, [abra uma issue](https://github.com/CorrectRoadH/OpenTickly/issues) com a versão, o passo que falhou e o log completo.

## Compatibilidade com o Toggl

O OpenTickly segue as APIs públicas do Toggl: Track v9, Reports v3 e Webhooks v1. CLIs, ferramentas MCP e integrações que funcionam com o Toggl devem continuar funcionando depois de cada atualização. Quando o Toggl adiciona ou muda um endpoint, a ideia é acompanhar na versão seguinte.
