Opisy wydań znajdziesz w GitHub Releases. Ta strona wyjaśnia, jak powstają wydania i jak przeprowadzić aktualizację.

- Najnowsze i starsze wydania: [github.com/CorrectRoadH/OpenTickly/releases](https://github.com/CorrectRoadH/OpenTickly/releases)
- Pełna historia commitów: [github.com/CorrectRoadH/OpenTickly/commits/main](https://github.com/CorrectRoadH/OpenTickly/commits/main)
- Obrazy Dockera: [hub.docker.com/r/correctroad/opentickly](https://hub.docker.com/r/correctroad/opentickly)

## Jak wypuszczamy wydania

Każde wydanie to tag gita na gałęzi `main`. Po otagowaniu automatycznie publikowany jest nowy obraz Dockera i aktualizowane jest demo pod adresem [track.opentoggl.com](https://track.opentoggl.com). Żeby zaktualizować własną instancję, uruchom `docker compose pull && docker compose up -d`.

## Uwagi dotyczące aktualizacji

Zwykle wystarczy po prostu zaktualizować, nic więcej nie trzeba robić. Baza danych aktualizuje się automatycznie przy starcie serwera, a API zgodne z Toggl się nie zmienia, więc Twoje integracje dalej działają.

Jeśli jakieś wydanie wymaga dodatkowych kroków, jego GitHub Release ma sekcję **Upgrade**, która je opisuje. Brak takiej sekcji oznacza zwykłą aktualizację.

Jeśli aktualizacja się nie powiedzie, [zgłoś problem](https://github.com/CorrectRoadH/OpenTickly/issues), podając wersję, krok, na którym coś poszło nie tak, i pełny log.

## Zgodność z Toggl

OpenTickly trzyma się publicznych API Toggl: Track v9, Reports v3 i Webhooks v1. CLI, narzędzia MCP i integracje, które działają z Toggl, powinny działać dalej po każdej aktualizacji. Gdy Toggl doda lub zmieni endpoint, staramy się nadrobić to w kolejnym wydaniu.
