Do uruchomienia OpenTickly u siebie wystarczy jeden plik `docker-compose.yml`. Poniżej opisujemy, jak przejść od zera do działającej instancji.

## Wymagania systemowe

- Dowolna maszyna z systemem Linux, macOS lub Windows z zainstalowanym **Docker Engine 20.10+** oraz **Docker Compose v2**
- Około 1 GB pamięci RAM i 1 GB miejsca na dysku
- Jeden wolny port TCP (domyślnie `8080`)

Jeśli nie masz jeszcze Dockera, najpierw zainstaluj go według [oficjalnej instrukcji](https://docs.docker.com/engine/install/).

---

## Wdrożenie serwera

### Krok 1 — Pobierz `docker-compose.yml`

Utwórz nowy katalog i pobierz plik compose:

```bash
mkdir -p opentickly && cd opentickly

wget -O docker-compose.yml \
  https://raw.githubusercontent.com/CorrectRoadH/OpenTickly/main/docker-compose.yml
```

Uruchamia on trzy kontenery:

- **OpenTickly** — interfejs webowy + REST API (dostępny na porcie `8080`)
- **`postgres`** — baza danych (tylko w sieci wewnętrznej, niedostępna z zewnątrz)
- **`redis`** — cache i zadania w tle (tylko w sieci wewnętrznej, niedostępny z zewnątrz)

### Krok 2 — (opcjonalnie) Skonfiguruj `.env`

Wartości domyślne działają od razu. Jeśli chcesz zmienić port lub hasła, utwórz w tym samym katalogu plik `.env`:

```bash
# Port, na którym dostępne są Web UI i API
OPENTOGGL_PORT=8080

# Zanim zaczniesz naprawdę korzystać, zmień na silne hasła
OPENTOGGL_POSTGRES_PASSWORD=postgres
OPENTOGGL_REDIS_PASSWORD=opentoggl
```

To **jedyne** trzy ustawienia, które możesz zmienić przez `.env`. Wszystko inne (nazwa bazy, użytkownik, obrazy, dane połączeń) jest celowo wpisane na stałe w pliku compose, żeby instalacje były proste i do siebie podobne. Jeśli chcesz zmienić coś więcej, edytuj bezpośrednio `docker-compose.yml`.

<Callout type="warn">
  Zanim zaczniesz naprawdę korzystać, zmień oba hasła. Wartości domyślne nadają się tylko do
  lokalnych testów. Postgres i Redis nie są dostępne spoza Dockera, ale jeśli ktoś przejmie inny
  komputer lub kontener w Twojej sieci, silne hasła nie pozwolą mu odczytać Twoich danych.
</Callout>

### Krok 3 — Uruchom kontenery

```bash
docker compose up -d
```

## Dostęp do aplikacji webowej

Otwórz w przeglądarce `http://<twój-IP>:8080`, zarejestruj pierwsze konto i możesz zacząć śledzić czas.

### Na telefonie

Aplikacji mobilnej jeszcze nie ma, ale możesz dodać aplikację webową do ekranu głównego telefonu i używać jej jak aplikacji (PWA). Rozmawiamy też z twórcami zewnętrznych aplikacji do Toggl, np. Timery, o obsłudze OpenTickly.

---

## Podłączenie agentów AI

OpenTickly nie ma limitu 30 zapytań na godzinę znanego z Toggl, więc Claude, Cursor i inni agenci mogą z niego korzystać, ile potrzebują. Skonfiguruj [`toggl-cli`](/pl/docs/ai-integration), a po kilku minutach agent będzie za Ciebie włączał i zatrzymywał timer oraz porządkował projekty.

## Aktualizacja

```bash
docker compose pull
docker compose up -d
```

## Wdrożenie na NAS / Homelab

OpenTickly działa wszędzie tam, gdzie działa Docker Compose. Poniższe kroki to ta sama instalacja, tylko wyklikana w interfejsie danego systemu.

### CasaOS

1. Otwórz panel CasaOS
2. Przejdź do **App Store** → **Custom Install** → **Import docker-compose**
3. Wklej zawartość [`docker-compose.yml`](https://raw.githubusercontent.com/CorrectRoadH/OpenTickly/main/docker-compose.yml)
4. Ustaw port **Web UI** na `8080` i zapisz
5. Uruchom aplikację z panelu

Wejdź pod `http://<twój-adres-CasaOS>:8080`.

### ZimaOS

ZimaOS (oficjalny system Zimablade / Zimacube) korzysta z tego samego App Store co CasaOS, więc kroki są identyczne: **App Store** → **Custom Install** → **Import docker-compose** i wklejasz plik compose.

### Synology

Synology DSM 7.2+ obsługuje Docker Compose poprzez **Container Manager**:

1. Otwórz **Container Manager** → **Projekt** → **Utwórz**
2. Nadaj nazwę projektu, np. `opentickly`
3. Wybierz **Użyj docker-compose.yml** i wklej [plik compose](https://raw.githubusercontent.com/CorrectRoadH/OpenTickly/main/docker-compose.yml)
4. Przejdź przez kreator, klikając dalej aż do końca

<Callout type="info">
  Jeśli port `8080` koliduje z DSM, przed utworzeniem projektu dodaj w ustawieniach środowiska
  `OPENTOGGL_PORT=9090` (lub dowolny wolny port).
</Callout>

### fnOS

[fnOS](https://www.fnnas.com) ma wbudowany panel Dockera:

1. Otwórz aplikację **Docker** z pulpitu fnOS
2. W lewym panelu wybierz **Compose** → **Nowy projekt**
3. Nazwij projekt `opentickly`, pozostaw domyślną ścieżkę zapisu
4. W polu **Zawartość Compose** wklej [plik compose](https://raw.githubusercontent.com/CorrectRoadH/OpenTickly/main/docker-compose.yml)
5. Kliknij **Wdróż** i poczekaj, aż wszystkie trzy kontenery zaświecą się na zielono

### Inne platformy

Poniższe platformy korzystają z tego samego procesu Docker Compose:

- **Unraid** — Community Applications lub wtyczka Compose Manager
- **TrueNAS SCALE** — niestandardowa aplikacja + Docker Compose
- **Proxmox LXC** — zainstaluj Docker w kontenerze LXC, a następnie postępuj według [wdrożenia serwera](#wdrożenie-serwera)

## Referencja konfiguracji

Przez `.env` możesz zmienić trzy ustawienia:

| Zmienna                       | Domyślna    | Opis                                           |
| ----------------------------- | ----------- | ---------------------------------------------- |
| `OPENTOGGL_PORT`              | `8080`      | Port, na którym działają Web UI i API          |
| `OPENTOGGL_POSTGRES_PASSWORD` | `postgres`  | Hasło Postgres (na produkcji koniecznie zmień) |
| `OPENTOGGL_REDIS_PASSWORD`    | `opentoggl` | Hasło Redis (na produkcji koniecznie zmień)    |

Wszystko inne (nazwa bazy, użytkownik, tagi obrazów, dane połączeń, nazwy wolumenów) jest ustawione bezpośrednio w `docker-compose.yml`. Jeśli chcesz to zmienić, edytuj ten plik.

### Punkty końcowe health check

| Ścieżka    | Zastosowanie                                    |
| ---------- | ----------------------------------------------- |
| `/readyz`  | Czy serwer jest gotowy? (sprawdza bazę i Redis) |
| `/healthz` | Czy proces działa?                              |
