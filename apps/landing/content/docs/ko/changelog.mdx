릴리스 노트는 GitHub Releases에 있습니다. 이 페이지에서는 릴리스가 나오는 방식과 업그레이드 방법을 설명합니다.

- 최신 및 이전 릴리스: [github.com/CorrectRoadH/OpenTickly/releases](https://github.com/CorrectRoadH/OpenTickly/releases)
- 전체 커밋 기록: [github.com/CorrectRoadH/OpenTickly/commits/main](https://github.com/CorrectRoadH/OpenTickly/commits/main)
- Docker 이미지: [hub.docker.com/r/correctroad/opentickly](https://hub.docker.com/r/correctroad/opentickly)

## 릴리스가 나오는 방식

릴리스마다 `main`에 git 태그가 하나씩 붙습니다. 태그를 붙이면 새 Docker 이미지가 자동으로 올라가고, 데모 사이트 [track.opentoggl.com](https://track.opentoggl.com)도 함께 업데이트됩니다. 셀프 호스팅 중이라면 `docker compose pull && docker compose up -d`로 업그레이드하세요.

## 업그레이드 안내

보통은 업그레이드만 하면 끝입니다. 데이터베이스는 서버가 시작될 때 자동으로 업데이트되고, Toggl 호환 API는 바뀌지 않으니 연동해 둔 도구도 그대로 동작합니다.

추가 작업이 필요한 릴리스라면 해당 GitHub Release에 **Upgrade** 섹션을 두고 무엇을 해야 하는지 설명합니다. 이 섹션이 없으면 평소처럼 업그레이드하면 됩니다.

업그레이드에 실패하면 버전, 실패한 단계, 전체 로그를 담아 [이슈를 열어](https://github.com/CorrectRoadH/OpenTickly/issues) 주세요.

## Toggl과의 호환성 유지

OpenTickly는 Toggl의 공개 API인 Track v9, Reports v3, Webhooks v1을 따릅니다. Toggl에서 동작하는 CLI, MCP 도구, 연동은 업그레이드 후에도 계속 동작해야 합니다. Toggl이 엔드포인트를 추가하거나 바꾸면 다음 릴리스에서 따라잡는 것을 목표로 합니다.
