새 계정을 만드는 것부터 첫 리포트를 보는 것까지 안내합니다. 먼저 데모로 써 봐도 되고, 내 서버에 OpenTickly를 직접 설치해도 됩니다.

## 사용 방식 고르기

| 방식        | 이런 분께                                  | 할 일                                                                   |
| ----------- | ------------------------------------------ | ----------------------------------------------------------------------- |
| 데모        | 설치 전에 일단 써 보고 싶은 분             | [track.opentoggl.com](https://track.opentoggl.com)에 접속해 계정 만들기 |
| 셀프 호스팅 | 앱과 데이터베이스를 내 서버에 두고 싶은 분 | [Docker 셀프 호스팅 안내](/ko/docs/self-hosting) 따라 하기              |

두 방식 모두 같은 앱입니다. 셀프 호스팅을 하면 데이터가 내 장비에만 남고, 대신 백업과 업그레이드는 직접 챙겨야 합니다.

## 계정과 워크스페이스 만들기

1. 이름, 이메일 주소, 비밀번호로 가입합니다.
2. 온보딩 중에 만들어진 워크스페이스를 엽니다.
3. 팀 기록을 시작하기 전에 워크스페이스 시간대를 확인합니다.
4. 첫 기록부터 프로젝트 리포트에 나오게 하고 싶다면 프로젝트를 하나 만듭니다.

프로젝트, 클라이언트, 태그, 멤버, 청구 요율, 시간 항목은 모두 워크스페이스 안에 있습니다. 리포트와 팀 공유도 워크스페이스 단위로 동작합니다.

## 첫 시간 기록하기

1. **타이머**를 엽니다.
2. `온보딩 가이드 작성`처럼 구체적인 설명을 입력합니다.
3. 프로젝트를 고르고, 필요하면 태그도 붙입니다.
4. 타이머를 시작하고, 일이 끝나면 정지합니다.

시작 시각과 종료 시각을 이미 알고 있다면 수동 모드를 쓰세요. 캘린더 보기와 목록 보기는 같은 기록을 보여 주니 편한 쪽에서 수정하면 됩니다.

## 시간을 어디에 썼는지 확인하기

**리포트**를 열고 기간을 고릅니다. 먼저 요약을 보고, 더 자세히 보고 싶으면 프로젝트, 클라이언트, 사용자, 태그, 청구 여부, 설명으로 필터링하거나 묶어 보세요.

처음에 확인해 볼 만한 것들:

- 합계가 기록하려던 시간과 맞나요?
- 기록이 올바른 프로젝트와 클라이언트에 들어가 있나요?
- 청구 가능한 기록과 아닌 기록이 제대로 나뉘어 있나요?
- 팀원들이 같은 종류의 일에 같은 태그를 쓰고 있나요?

## 기존 데이터나 연동 가져오기

- Toggl Track에서 옮겨 오려면 [Toggl에서 OpenTickly로 마이그레이션](/ko/docs/migrate-from-toggl)을 따라 하세요.
- 쓰던 CLI, 스크립트, 에이전트를 계속 쓰려면 [Toggl API 호환성](/ko/docs/api-compatibility)을 읽어 보세요.
- 에이전트로 시간 기록을 자동화하려면 [toggl-cli와 AI 에이전트](/ko/docs/ai-integration)를 연결하세요.

## 다음으로 해 볼 일

1. 리포트에서 보고 싶은 모양대로 클라이언트와 프로젝트를 정리합니다.
2. 팀원을 초대하고 역할을 확인합니다.
3. 셀프 호스팅 중이라면 데이터베이스 백업을 설정합니다.
4. 매일 타이머 확인하기, 매주 프로젝트 리포트 보기처럼 돌아보는 습관을 하나 만듭니다.

프로젝트와 태그는 꾸준히 지킬 수 있을 만큼만 적게 시작하세요. 정말 보고 싶은 리포트에 필요해질 때 하나씩 늘리면 됩니다.
