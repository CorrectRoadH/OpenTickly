---
title: "백업, 복원, 업그레이드"
description: "PostgreSQL을 백업하고 복원을 확인한 다음 업데이트하세요."
---

앱 데이터, 업로드한 파일, 가져오기 압축 파일은 PostgreSQL에 저장됩니다. Compose의 데이터베이스는 `opentoggl`, 사용자와 서비스는 `postgres`, 볼륨은 `opentoggl-postgres-data-pg19`입니다. Redis는 영구 저장을 사용하지 않으므로 백업할 필요가 없습니다.

## 백업하기

`docker-compose.yml`이 있는 디렉터리에서 실행합니다.

```bash
docker compose exec -T postgres pg_dump -U postgres -d opentoggl -Fc > backup.dump
```

다른 서버에도 사본을 보관하세요. `docker-compose.yml`, `.env`, 프록시 설정은 데이터베이스 덤프에 포함되지 않으므로 별도로 안전하게 보관합니다.

매일 백업하려면 `/srv/backups`를 만들고 경로와 Docker 실행 파일 위치를 수정한 다음, Docker 권한이 있는 사용자의 crontab에 추가합니다.

```text
0 2 * * * cd /srv/opentickly && umask 077 && /usr/bin/docker compose exec -T postgres pg_dump -U postgres -d opentoggl -Fc > /srv/backups/opentickly-$(date +\%F).dump
```

작업이 성공했는지 확인하고 정기적으로 복원을 시험하세요. 파일이 존재한다는 것만으로 복원 가능 여부를 알 수는 없습니다.

## 복원하기

먼저 별도 인스턴스에서 시험합니다. 복원은 백업된 데이터베이스 객체를 덮어쓰며, 백업 이후 변경 사항은 사라집니다. 백업 당시 앱 버전을 사용하고 PostgreSQL이 실행 중인지 확인합니다.

```bash
docker compose stop opentoggl &&
  docker compose exec -T postgres pg_restore -U postgres -d opentoggl --clean --if-exists --exit-on-error < backup.dump &&
  docker compose up -d opentoggl
```

`pg_restore`가 실패하면 오류를 해결할 때까지 앱을 중지해 두세요. 복원 후 로그인하여 시간 기록과 파일을 확인합니다. 데이터베이스 볼륨은 삭제하지 마세요.

## 업데이트와 되돌리기

기존 Compose 파일이 `postgres:17-alpine`을 사용한다면 아래 PostgreSQL 업그레이드 단계부터 진행하세요.

1. 백업하고 현재 이미지 버전이나 digest를 기록합니다. `latest`는 바뀔 수 있어 이전 버전을 특정할 수 없습니다.
2. 다음을 실행합니다.

```bash
docker compose pull && docker compose up -d
```

3. 서버가 시작될 때 데이터베이스 구조가 자동으로 업데이트됩니다. `docker compose logs opentoggl`을 확인하고 로그인해 데이터를 점검합니다.

되돌리려면 `opentoggl`을 중지하고 `docker-compose.yml`에서 이전 이미지 태그나 digest를 지정한 뒤 해당 이미지를 받습니다. 이어서 위 절차대로 업데이트 전 백업을 복원합니다. 업데이트된 데이터베이스에 예전 이미지만 연결하지 마세요. 백업 이후 변경 사항은 사라집니다.

## Docker Compose에서 PostgreSQL 17을 19로 업그레이드하기

PostgreSQL 17 Compose 파일을 교체하기 전에 `docker-compose.pg17.yml`로 사본을 저장하고 데이터를 백업하세요. 기존 Compose 프로젝트 이름과 비밀번호를 그대로 사용하세요. 새 볼륨에는 이전 클러스터 크기의 1.2배 이상의 여유 공간이 필요합니다. 최초 업그레이드에는 Alpine 패키지 저장소에 대한 인터넷 접속도 필요합니다.

`docker-compose.yml`을 새 버전으로 교체하고 `docker compose up -d`를 실행하세요. PostgreSQL과 OpenTickly가 시작되기 전에 `postgres-upgrade` 서비스가 클러스터를 새 볼륨에 복사합니다. 새 설치와 이미 업그레이드된 설치에서는 복사를 건너뜁니다. 로그인하여 시간 기록과 업로드한 파일을 확인하세요.

시작에 실패하면 `docker compose logs postgres-upgrade`로 오류를 확인하세요. 원인을 해결한 뒤 `docker compose up -d`를 다시 실행하세요. 수동으로 이전하려면 기존 Compose 환경을 시작하고 위의 백업 명령을 실행하세요. 기존 환경을 정지한 뒤 새 Compose 파일과 빈 PostgreSQL 19 볼륨으로 아래 명령을 실행하세요.

```sh
docker compose up -d --no-deps --wait postgres &&
  docker compose exec -T postgres pg_restore -U postgres -d opentoggl --single-transaction < backup.dump &&
  docker compose up -d
```

되돌리려면 같은 디렉터리에서 `docker compose -f docker-compose.pg17.yml up -d --remove-orphans`를 실행하세요. 기존 볼륨에는 업그레이드 전 데이터가 남아 있습니다. PostgreSQL 19로 전환한 뒤 작성된 데이터는 새 볼륨에 남습니다.

새 인스턴스를 확인하고 백업한 뒤 디스크 공간을 확보할 수 있습니다. 완료된 업그레이드 컨테이너를 삭제한 뒤 기존 볼륨을 삭제하세요. 사용자 지정 프로젝트 이름을 썼다면 `opentoggl-self-hosted`를 해당 이름으로 바꾸세요. 기존 볼륨을 삭제하면 되돌리기용 로컬 사본도 사라집니다.

```sh
docker compose rm -f postgres-upgrade &&
  docker volume rm opentoggl-self-hosted_opentoggl-postgres-data
```
