title: Toggl에서 OpenTickly로 마이그레이션
description: Toggl Track 데이터를 OpenTickly로 옮기는 방법입니다. 계정 내보내기 ZIP과 시간 항목 CSV를 가져온 뒤 모두 잘 들어왔는지 확인합니다.
---

Toggl Track 계정은 하나하나 다시 만들 필요 없이 그대로 옮겨 올 수 있습니다. 두 단계면 됩니다. 먼저 계정 내보내기 ZIP을 가져와 워크스페이스, 프로젝트, 클라이언트, 태그, 멤버를 옮기고, 그다음 시간 항목 CSV를 가져와 실제 기록을 옮깁니다.

<Callout type="info">
  합계가 맞는지 확인할 때까지 원본 내보내기 파일은 지우지 마세요. 가져오기가 Toggl 계정 백업을
  대신해 주지는 않습니다.
</Callout>

## 옮기기 전에

1. 데이터를 받을 OpenTickly 계정을 만들거나 로그인합니다.
2. 셀프 호스팅 중이라면 서버 디스크 공간이 충분한지 확인합니다.
3. 옮겨 갈 시점을 정하고 Toggl에서는 기록을 멈춥니다. 그래야 양쪽에 기록이 나뉘지 않습니다.
4. 각 CSV가 어느 워크스페이스, 어느 기간의 기록인지 적어 둡니다.

## 1단계: Toggl 계정 데이터 내보내기

[Toggl Track 설정](https://track.toggl.com/settings)에서 데이터 내보내기를 요청합니다. ZIP을 내려받고 안의 내용은 건드리지 마세요.

이 파일을 가져오면 OpenTickly에 새 조직이 하나 생깁니다. OpenTickly 웹 앱에서:

1. **가져오기**를 엽니다.
2. 가져올 조직의 이름을 입력합니다.
3. Toggl 내보내기 ZIP을 선택합니다.
4. 가져오기를 시작하고, 성공 또는 실패가 표시될 때까지 기다립니다.

가져오기는 백그라운드에서 진행됩니다. 진행 중에 같은 ZIP을 다시 올리지 마세요.

## 2단계: 상세 시간 항목 가져오기

Toggl에서 필요한 기간의 상세 시간 항목 리포트를 CSV로 내보냅니다. 그다음 다시 **가져오기**에서:

1. 가져올 조직과 워크스페이스를 고릅니다.
2. CSV 파일을 하나 이상 선택합니다.
3. 업로드하고 파일마다 끝날 때까지 기다립니다.
4. 다른 워크스페이스로 가져오기 전에 워크스페이스가 제대로 선택됐는지 한 번 더 확인합니다.

`consulting-2025-q4.csv`처럼 파일 이름에 워크스페이스와 기간을 넣어 두면 빠진 기간이나 중복을 찾기 쉽습니다.

## 결과 확인하기

OpenTickly에서 본격적으로 기록을 시작하기 전에:

- 조직과 워크스페이스 이름을 비교합니다.
- 클라이언트, 프로젝트, 태그, 멤버를 몇 개 골라 확인합니다.
- **리포트**에서 하루, 한 주, 한 달 합계를 Toggl과 비교합니다.
- 진행 중인 기록과 자정을 넘긴 기록을 확인합니다.
- 기록 몇 개를 골라 청구 여부, 시간, 설명, 프로젝트, 사용자, 태그를 확인합니다.
- 가져오기가 실패하면 다시 시도하거나 이슈를 열기 전에 오류 메시지를 복사해 둡니다.

리포트 합계를 비교하는 게 문제를 가장 빨리 찾는 방법입니다. 빠진 기간, 엉뚱한 워크스페이스에 들어간 기록, 같은 CSV를 두 번 가져온 경우가 바로 드러납니다.

## 옮겨 가기

숫자가 맞으면 팀에 이제부터 OpenTickly에서 기록하자고 알려 주세요. 혹시 되돌아가야 할 때를 대비해 Toggl 내보내기 파일과 OpenTickly 데이터베이스 백업은 한동안 보관하세요.

다음으로 평소 사용법은 [시작하기](/ko/docs/getting-started)를, 스크립트와 연동을 옮기려면 [API 호환성](/ko/docs/api-compatibility)을 보세요.

전환 전에 [백업, 복원, 업그레이드](/ko/docs/backup-and-upgrade)를 따라 OpenTickly를 복원할 준비를 하세요. Toggl로 돌아갈 때 필요한 CSV 수정 방법과 제한은 [데이터 내보내기](/ko/docs/export-data)에서 확인할 수 있습니다.
