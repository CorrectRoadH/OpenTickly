这篇指南带你从空账号走到第一份可用报表。你可以先体验在线版本，也可以直接把同一套应用部署在自己的基础设施上。

## 选择使用方式

| 方式     | 适合谁                           | 怎么开始                                                           |
| -------- | -------------------------------- | ------------------------------------------------------------------ |
| 在线体验 | 想先确认界面和工作流是否合适     | 打开 [track.opentoggl.com](https://track.opentoggl.com) 并注册账号 |
| 自托管   | 想自己掌控应用、数据库和升级节奏 | 阅读 [Docker 自托管指南](/zh/docs/self-hosting)                    |

两种方式使用相同的核心工作流。自托管时，应用、PostgreSQL 数据库、备份、网络入口和升级时间都由你管理。

## 创建账号和工作区

1. 使用姓名、邮箱和密码注册。
2. 打开引导流程创建的工作区。
3. 在团队开始记时前确认工作区时区。
4. 如果希望第一条记录进入项目报表，先创建一个项目。

工作区是协作和报表的边界。客户、项目、标签、成员、费率和时间记录都属于某个工作区。

## 记录第一条时间

1. 打开 **计时器**。
2. 输入清楚的描述，例如“编写上手文档”。
3. 选择项目和可选标签。
4. 开始计时，工作完成后停止。

如果已经知道开始和结束时间，可以使用手动记录。日历视图和列表视图操作的是同一批记录，可以按任务选择更顺手的编辑方式。

## 查看时间去了哪里

打开 **报表** 并选择日期范围。先看汇总，再按项目、客户、成员、标签、计费状态或描述筛选和分组。

新工作区值得检查这些问题：

- 总时长是否符合预期？
- 时间是否归到了正确的项目和客户？
- 计费与非计费时间是否区分正确？
- 团队成员是否用相同标签表示相同类型的工作？

## 接入已有数据和工具

- 从 Toggl Track 搬迁：阅读[从 Toggl 迁移到 OpenTickly](/zh/docs/migrate-from-toggl)。
- 复用 CLI、脚本或 Agent：阅读 [Toggl API 兼容说明](/zh/docs/api-compatibility)。
- 让 Agent 自动记录时间：接入 [toggl-cli 和 AI Agent](/zh/docs/ai-integration)。

## 建议的下一步

1. 按真实报表需求创建客户和项目。
2. 邀请团队成员并核对工作区角色。
3. 为自托管数据库安排备份。
4. 建立一个可重复的习惯，例如每天检查计时器或每周查看项目报表。

描述、项目和标签能够回答实际问题时，时间数据才有价值。先采用一套最小但能长期坚持的结构，只有报表确实需要时再增加细节。
