---

Para tener tu propio OpenTickly solo necesitas un archivo `docker-compose.yml`. Aquí tienes cómo pasar de cero a una instancia funcionando.

## Requisitos del sistema

- Cualquier máquina Linux, macOS o Windows con **Docker Engine 20.10+** y **Docker Compose v2**
- Alrededor de 1 GB de RAM y 1 GB de disco
- Un puerto TCP libre (por defecto `8080`)

Si todavía no tienes Docker, sigue primero la [guía oficial de instalación](https://docs.docker.com/engine/install/).

---

## Desplegar el servidor

### Paso 1 — Descarga el `docker-compose.yml`

Crea una carpeta nueva y descarga el archivo compose:

```bash
mkdir -p opentickly && cd opentickly

wget -O docker-compose.yml \
  https://raw.githubusercontent.com/CorrectRoadH/OpenTickly/main/docker-compose.yml
```

Arranca tres contenedores:

- **OpenTickly** — Web UI + API REST (en el puerto `8080`)
- **`postgres`** — Base de datos (solo en la red interna, no accesible desde fuera)
- **`redis`** — Caché y tareas en segundo plano (solo en la red interna, no accesible desde fuera)

### Paso 2 — (Opcional) configura `.env`

Funciona tal cual con los valores por defecto. Si quieres cambiar el puerto o las contraseñas, crea un archivo `.env` en la misma carpeta:

```bash
# Puerto de la Web UI y la API
OPENTOGGL_PORT=8080

# Cámbialas por contraseñas seguras antes de usarlo de verdad
OPENTOGGL_POSTGRES_PASSWORD=postgres
OPENTOGGL_REDIS_PASSWORD=opentoggl
```

Estos tres son los **únicos** ajustes que puedes cambiar desde `.env`. Todo lo demás (nombre de la base de datos, usuario, imágenes, cadenas de conexión) está fijo en el archivo compose a propósito, para que todas las instalaciones sean sencillas y parecidas. Si quieres cambiar algo más, edita directamente el `docker-compose.yml`.

<Callout type="warn">
  Cambia las dos contraseñas antes de usarlo de verdad. Los valores por defecto solo valen para
  probarlo en local. Postgres y Redis no son accesibles desde fuera de Docker, pero si otra máquina
  o contenedor de tu red queda comprometido, unas contraseñas seguras evitan que lea tus datos.
</Callout>

### Paso 3 — Arranca los contenedores

```bash
docker compose up -d
```

---

## Acceder a la aplicación web

Abre `http://<tu-IP>:8080` en el navegador, registra la primera cuenta y empieza a registrar tiempo.

### Móvil

Todavía no hay aplicación móvil, pero puedes añadir la web a la pantalla de inicio del teléfono y usarla como si lo fuera (PWA). También estamos hablando con desarrolladores de apps de Toggl de terceros, como Timery, para que sean compatibles con OpenTickly.

---

## Conectar agentes de IA

OpenTickly no tiene el límite de 30 peticiones por hora de Toggl, así que Claude, Cursor y otros agentes pueden usarlo todo lo que necesiten. Configura [`toggl-cli`](/es/docs/ai-integration) y en unos minutos tu agente podrá iniciar y parar temporizadores y organizarte los proyectos.

## Actualizar

```bash
docker compose pull
docker compose up -d
```

## Desplegar en NAS / Homelab

OpenTickly funciona en cualquier sitio donde funcione Docker Compose. Los pasos de abajo son la misma instalación, hecha desde la interfaz de cada plataforma.

### CasaOS

1. Abre el panel de control de CasaOS
2. Ve a **App Store** → **Instalación personalizada** → **Importar docker-compose**
3. Pega el contenido de [`docker-compose.yml`](https://raw.githubusercontent.com/CorrectRoadH/OpenTickly/main/docker-compose.yml)
4. Pon el puerto de la **Web UI** en `8080` y guarda
5. Arranca la app desde el panel de control

Entra en `http://<tu-IP-CasaOS>:8080`.

### ZimaOS

ZimaOS (el sistema oficial de Zimablade / Zimacube) usa la misma App Store que CasaOS, así que los pasos son los mismos: **App Store** → **Instalación personalizada** → **Importar docker-compose** y pega el archivo compose.

### Synology

Synology DSM 7.2+ admite Docker Compose a través de **Container Manager**:

1. Abre **Container Manager** → **Proyecto** → **Crear**
2. Ponle un nombre al proyecto, por ejemplo `opentickly`
3. Elige **Usar docker-compose.yml** y pega el [archivo compose](https://raw.githubusercontent.com/CorrectRoadH/OpenTickly/main/docker-compose.yml)
4. Sigue el asistente hasta el final

<Callout type="info">
  Si el `8080` choca con DSM, añade `OPENTOGGL_PORT=9090` (o cualquier puerto libre) en los ajustes
  de entorno antes de crear el proyecto.
</Callout>

### fnOS

[fnOS](https://www.fnnas.com) trae su propio panel de Docker:

1. Abre la app **Docker** desde el escritorio de fnOS
2. En la barra lateral izquierda, elige **Compose** → **Nuevo proyecto**
3. Nombre del proyecto `opentickly`; deja la ruta de almacenamiento por defecto
4. Pega el [archivo compose](https://raw.githubusercontent.com/CorrectRoadH/OpenTickly/main/docker-compose.yml) en **Contenido Compose**
5. Pulsa **Desplegar** y espera a que los tres contenedores se pongan en verde

### Otras plataformas

Estas plataformas siguen el mismo proceso con Docker Compose:

- **Unraid** — con Community Applications o el plugin Compose Manager
- **TrueNAS SCALE** — app personalizada + Docker Compose
- **Proxmox LXC** — instala Docker dentro de un contenedor LXC y luego sigue los pasos de [Desplegar el servidor](#desplegar-el-servidor)

## Referencia de configuración

Puedes cambiar tres ajustes desde `.env`:

| Variable                      | Por defecto | Descripción                                     |
| ----------------------------- | ----------- | ----------------------------------------------- |
| `OPENTOGGL_PORT`              | `8080`      | Puerto de la Web UI y la API                    |
| `OPENTOGGL_POSTGRES_PASSWORD` | `postgres`  | Contraseña de Postgres (cámbiala en producción) |
| `OPENTOGGL_REDIS_PASSWORD`    | `opentoggl` | Contraseña de Redis (cámbiala en producción)    |

Todo lo demás (nombre de la base de datos, usuario, versiones de las imágenes, cadenas de conexión, nombres de los volúmenes) está definido directamente en el `docker-compose.yml`. Si quieres cambiarlo, edita el archivo.

### Endpoints de comprobación de estado

| Ruta       | Para qué sirve                                   |
| ---------- | ------------------------------------------------ |
| `/readyz`  | ¿Está listo para atender? (comprueba BD + Redis) |
| `/healthz` | ¿Está el proceso en marcha?                      |
