Las notas de cada versión están en GitHub Releases. Esta página explica cómo se publican las versiones y cómo actualizar.

- Versiones actuales y anteriores: [github.com/CorrectRoadH/OpenTickly/releases](https://github.com/CorrectRoadH/OpenTickly/releases)
- Historial completo de commits: [github.com/CorrectRoadH/OpenTickly/commits/main](https://github.com/CorrectRoadH/OpenTickly/commits/main)
- Imágenes Docker: [hub.docker.com/r/correctroad/opentickly](https://hub.docker.com/r/correctroad/opentickly)

## Cómo se publican las versiones

Cada versión es un tag de git en `main`. Al crear el tag se publica automáticamente una nueva imagen Docker y se actualiza la demo de [track.opentoggl.com](https://track.opentoggl.com). Para actualizar una instancia autoalojada, ejecuta `docker compose pull && docker compose up -d`.

## Notas de actualización

Normalmente basta con actualizar, no hay que hacer nada más. La base de datos se actualiza sola al arrancar el servidor y la API compatible con Toggl no cambia, así que tus integraciones siguen funcionando.

Si una versión necesita pasos extra, su GitHub Release incluye una sección **Upgrade** que los explica. Si no hay esa sección, es una actualización normal.

Si una actualización falla, [abre un issue](https://github.com/CorrectRoadH/OpenTickly/issues) con la versión, el paso que falló y el log completo.

## Compatibilidad con Toggl

OpenTickly sigue las API públicas de Toggl: Track v9, Reports v3 y Webhooks v1. Los CLI, herramientas MCP e integraciones que funcionan con Toggl deberían seguir funcionando después de cada actualización. Cuando Toggl añade o cambia un endpoint, intentamos ponernos al día en la siguiente versión.
