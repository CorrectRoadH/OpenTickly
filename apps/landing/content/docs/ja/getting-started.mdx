このガイドでは、アカウントを作ってから最初のレポートを見るところまでを案内します。まずはデモで試してもいいですし、自分のサーバーで OpenTickly を動かしてもかまいません。

## 使い方を選ぶ

| 方法         | 向いている人                                         | やること                                                                    |
| ------------ | ---------------------------------------------------- | --------------------------------------------------------------------------- |
| デモ         | 何もインストールせずにまず試してみたい               | [track.opentoggl.com](https://track.opentoggl.com) を開いてアカウントを作る |
| セルフホスト | アプリとデータベースを自分のサーバーに置いておきたい | [Docker セルフホストガイド](/ja/docs/self-hosting) に沿って導入する         |

どちらも中身は同じアプリです。セルフホストならデータは自分のマシンに置いたままにできますが、バックアップとアップグレードは自分で行います。

## アカウントとワークスペースを作る

1. 名前、メールアドレス、パスワードで登録します。
2. 初期設定で作られたワークスペースを開きます。
3. チームで記録を始める前に、ワークスペースのタイムゾーンを確認します。
4. 最初の記録をプロジェクト別のレポートに出したいなら、プロジェクトを作っておきます。

プロジェクト、クライアント、タグ、メンバー、請求単価、時間エントリは、すべてワークスペースの中にあります。レポートやチームでの共有もワークスペース単位です。

## 最初の時間を記録する

1. **タイマー** を開きます。
2. `オンボーディングガイドを書く` のように、具体的な説明を入力します。
3. プロジェクトと、必要ならタグを選びます。
4. タイマーを開始し、作業が終わったら停止します。

開始・終了時刻がもう分かっているなら、手動入力モードを使いましょう。カレンダー表示とリスト表示には同じエントリが出るので、どちらで編集してもかまいません。

## 時間の使い方を振り返る

**レポート** を開いて期間を選びます。まずはサマリーを見て、もっと詳しく知りたくなったら、プロジェクト、クライアント、ユーザー、タグ、請求可否、説明で絞り込んだりグループ化したりします。

最初のうちに確認しておくといいこと：

- 合計は、記録したつもりの時間と合っていますか？
- エントリは正しいプロジェクトとクライアントに割り当てられていますか？
- 請求対象と請求対象外のエントリはきちんと分かれていますか？
- 同じ種類の作業に、メンバーが同じタグを使っていますか？

## 既存のデータや連携を持ってくる

- Toggl Track から移る場合：[Toggl から OpenTickly へ移行](/ja/docs/migrate-from-toggl) の手順に従います。
- 既存の CLI、スクリプト、エージェントを使い続けたい場合：[Toggl API 互換性](/ja/docs/api-compatibility) を読みます。
- エージェントに時間の記録を任せたい場合：[toggl-cli と AI エージェント](/ja/docs/ai-integration) をつなぎます。

## 次にやること

1. レポートで見たい形に合わせて、クライアントとプロジェクトを整えます。
2. チームメンバーを招待し、ロールを確認します。
3. セルフホストしているなら、[データベースのバックアップを設定します](/ja/docs/backup-and-upgrade)。
4. 毎日タイマーを確認する、毎週プロジェクトレポートを見る、など振り返りの習慣を 1 つ作ります。

プロジェクトとタグは、続けられる範囲でできるだけ少なく始めましょう。本当に見たいレポートに必要になったときだけ増やせば十分です。
