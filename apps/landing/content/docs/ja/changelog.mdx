リリースノートは GitHub Releases にあります。このページでは、リリースの流れとアップグレードの方法を説明します。

- 最新および過去のリリース：[github.com/CorrectRoadH/OpenTickly/releases](https://github.com/CorrectRoadH/OpenTickly/releases)
- コミット履歴全体：[github.com/CorrectRoadH/OpenTickly/commits/main](https://github.com/CorrectRoadH/OpenTickly/commits/main)
- Docker イメージ：[hub.docker.com/r/correctroad/opentickly](https://hub.docker.com/r/correctroad/opentickly)

## リリースの流れ

リリースは `main` に付けた git タグ 1 つにつき 1 回です。タグを付けると、新しい Docker イメージが自動で公開され、デモ環境 [track.opentoggl.com](https://track.opentoggl.com) も更新されます。セルフホストのインスタンスをアップグレードするには、`docker compose pull && docker compose up -d` を実行します。

## アップグレード時の注意

ふつうはアップグレードするだけで、ほかに何もする必要はありません。データベースはサーバーの起動時に自動で更新されますし、Toggl 互換の API も変わらないので、連携しているツールもそのまま動きます。

追加の手順が必要なリリースでは、その GitHub Release に **Upgrade** セクションがあり、やることが書いてあります。このセクションがなければ、通常どおりアップグレードして大丈夫です。

アップグレードに失敗したら、バージョン、失敗した手順、ログ全体を添えて [Issue を立ててください](https://github.com/CorrectRoadH/OpenTickly/issues)。

## Toggl との互換性を保つ

OpenTickly は Toggl の公開 API（Track v9、Reports v3、Webhooks v1）に合わせています。Toggl で動く CLI、MCP ツール、連携は、アップグレード後も動き続けるはずです。Toggl がエンドポイントを追加・変更したときは、次のリリースで追いつくようにしています。
