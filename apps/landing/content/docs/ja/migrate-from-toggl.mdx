---
title: Toggl から OpenTickly へ移行
description: Toggl Track のデータを OpenTickly に移します。アカウントのエクスポート ZIP と時間エントリの CSV を取り込み、すべて揃っているか確認します。
---

Toggl Track のアカウントは、何も手で作り直さずに OpenTickly へ持ってこられます。手順は 2 つです。まずアカウントのエクスポート ZIP を取り込んでワークスペース、プロジェクト、クライアント、タグ、メンバーを移し、次に時間エントリの CSV を取り込んで実際の記録を移します。

<Callout type="info">
  合計が一致することを確認するまで、元のエクスポートファイルは消さないでください。インポートは Toggl
  アカウントのバックアップの代わりにはなりません。
</Callout>

## 移行の前に

1. 移行先の OpenTickly アカウントを作るか、サインインします。
2. セルフホストしているなら、サーバーのディスクに十分な空きがあるか確認します。
3. 切り替えのタイミングを決めて Toggl での記録を止めます。両方にエントリができてしまうのを防ぐためです。
4. それぞれの CSV がどのワークスペースのどの期間なのかをメモしておきます。

## ステップ 1：Toggl のアカウントデータをエクスポートする

[Toggl Track の設定](https://track.toggl.com/settings) を開き、データエクスポートを申請します。ZIP をダウンロードしたら、中身は変更しないでください。

これを取り込むと、OpenTickly に新しい組織ができます。OpenTickly の Web アプリで：

1. **インポート** を開きます。
2. 取り込む組織の名前を入力します。
3. Toggl のエクスポート ZIP を選びます。
4. インポートを開始し、成功か失敗かが表示されるまで待ちます。

インポートはバックグラウンドで進みます。終わるまでは同じ ZIP をもう一度アップロードしないでください。

## ステップ 2：時間エントリの詳細を取り込む

Toggl で、必要な期間の時間エントリ詳細レポートを CSV でエクスポートします。それから **インポート** に戻って：

1. 取り込み先の組織とワークスペースを選びます。
2. CSV ファイルを 1 つ以上選びます。
3. アップロードして、それぞれが終わるまで待ちます。
4. 別のワークスペースに取り込む前に、正しいワークスペースが選ばれているかもう一度確認します。

`consulting-2025-q4.csv` のように、ファイル名にワークスペースと期間を入れておくと、抜けや重複に気づきやすくなります。

## 結果を確認する

OpenTickly で本格的に記録を始める前に：

- 組織とワークスペースの名前を見比べます。
- クライアント、プロジェクト、タグ、メンバーをいくつか抜き出して確認します。
- **レポート** で 1 日、1 週間、1 か月の合計を Toggl と比べます。
- 実行中のエントリと、日付をまたぐエントリを確認します。
- いくつかのエントリで、請求可否、時間、説明、プロジェクト、ユーザー、タグを確認します。
- インポートに失敗したら、再試行や Issue を立てる前にエラーメッセージをコピーしておきます。

レポートの合計を比べるのが、問題を見つけるいちばん手っ取り早い方法です。期間の抜け、別のワークスペースに入ったエントリ、同じ CSV の二重取り込みなどがすぐに分かります。

## 切り替える

数字が合ったら、これからは OpenTickly で記録するようチームに伝えましょう。元に戻す必要が出たときのために、Toggl のエクスポートファイルと OpenTickly のデータベースのバックアップはしばらく残しておきます。

次は、日々の使い方なら [入門](/ja/docs/getting-started) を、スクリプトや連携を移すなら [API 互換性](/ja/docs/api-compatibility) をどうぞ。

切り替える前に[バックアップ・復元・アップグレード](/ja/docs/backup-and-upgrade)に従って備え、必要なら OpenTickly を復元できるようにします。Toggl に戻す場合の CSV の整え方と制限は、[データのエクスポート](/ja/docs/export-data)をご覧ください。
