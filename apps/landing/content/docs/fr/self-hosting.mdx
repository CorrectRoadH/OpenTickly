Pour faire tourner OpenTickly chez vous, il suffit d'un fichier `docker-compose.yml`. Voici comment passer de rien à une instance qui fonctionne.

## Prérequis système

- N'importe quelle machine Linux, macOS ou Windows avec **Docker Engine 20.10+** et **Docker Compose v2**
- Environ 1 Go de mémoire et 1 Go d'espace disque
- Un port TCP libre (par défaut `8080`)

Si vous n'avez pas encore Docker, suivez d'abord le [guide d'installation officiel](https://docs.docker.com/engine/install/).

---

## Déployer le serveur

### Étape 1 — Télécharger `docker-compose.yml`

Créez un nouveau dossier et téléchargez le fichier compose :

```bash
mkdir -p opentickly && cd opentickly

wget -O docker-compose.yml \
  https://raw.githubusercontent.com/CorrectRoadH/OpenTickly/main/docker-compose.yml
```

Il lance trois conteneurs :

- **OpenTickly** — interface web + API REST (accessible sur le port `8080`)
- **`postgres`** — base de données (réseau interne uniquement, inaccessible de l'extérieur)
- **`redis`** — cache et tâches d'arrière-plan (réseau interne uniquement, inaccessible de l'extérieur)

### Étape 2 — (Optionnel) Configurer `.env`

Les valeurs par défaut fonctionnent telles quelles. Pour changer le port ou les mots de passe, créez un fichier `.env` dans le même dossier :

```bash
# Port de l'interface web et de l'API
OPENTOGGL_PORT=8080

# Remplacez-les par des mots de passe solides avant une vraie utilisation
OPENTOGGL_POSTGRES_PASSWORD=postgres
OPENTOGGL_REDIS_PASSWORD=opentoggl
```

Ce sont les **seuls** réglages modifiables via `.env`. Tout le reste (nom de la base, utilisateur, images, chaînes de connexion) est fixé volontairement dans le fichier compose, pour que les installations restent simples et identiques. Pour aller plus loin, modifiez directement `docker-compose.yml`.

<Callout type="warn">
  Changez les deux mots de passe avant une vraie utilisation. Les valeurs par défaut ne conviennent
  que pour un essai en local. Postgres et Redis ne sont pas joignables depuis l'extérieur de Docker,
  mais si une autre machine ou un autre conteneur de votre réseau est piraté, des mots de passe
  solides l'empêchent de lire vos données.
</Callout>

### Étape 3 — Démarrer les conteneurs

```bash
docker compose up -d
```

## Accéder à l'application Web

Ouvrez `http://<votre-ip>:8080` dans votre navigateur, créez le premier compte et commencez à enregistrer votre temps.

### Sur mobile

Il n'y a pas encore d'application mobile, mais vous pouvez ajouter l'application web à l'écran d'accueil de votre téléphone et l'utiliser comme une app (PWA). On discute aussi avec les développeurs d'applications Toggl tierces, comme Timery, pour qu'elles prennent en charge OpenTickly.

---

## Connecter les agents IA

OpenTickly n'a pas la limite de 30 requêtes par heure de Toggl : Claude, Cursor et les autres agents peuvent donc s'en servir autant qu'ils en ont besoin. Installez [`toggl-cli`](/fr/docs/ai-integration) et, en quelques minutes, votre agent pourra démarrer et arrêter vos minuteurs et ranger vos projets à votre place.

## Mise à jour

```bash
docker compose pull
docker compose up -d
```

## Déployer sur NAS / Homelab

OpenTickly tourne partout où Docker Compose fonctionne. Les étapes ci-dessous reprennent la même installation, faite depuis l'interface de chaque plateforme.

### CasaOS

1. Ouvrez le tableau de bord CasaOS
2. Allez dans **App Store** → **Installation personnalisée** → **Importer docker-compose**
3. Collez le contenu de [`docker-compose.yml`](https://raw.githubusercontent.com/CorrectRoadH/OpenTickly/main/docker-compose.yml)
4. Réglez le port **Web UI** sur `8080` puis enregistrez
5. Lancez l'app depuis le tableau de bord

Accédez-y via `http://<votre-ip-casaos>:8080`.

### ZimaOS

ZimaOS (le système officiel des Zimablade / Zimacube) partage le même App Store que CasaOS, les étapes sont donc les mêmes : **App Store** → **Installation personnalisée** → **Importer docker-compose**, puis collez le fichier compose.

### Synology

Synology DSM 7.2+ prend en charge Docker Compose via **Container Manager** :

1. Ouvrez **Container Manager** → **Projet** → **Créer**
2. Donnez un nom au projet, par exemple `opentickly`
3. Choisissez **Utiliser docker-compose.yml** et collez le [fichier compose](https://raw.githubusercontent.com/CorrectRoadH/OpenTickly/main/docker-compose.yml)
4. Suivez l'assistant jusqu'au bout

<Callout type="info">
  Si le port `8080` entre en conflit avec DSM, ajoutez `OPENTOGGL_PORT=9090` (ou tout autre port
  libre) dans les paramètres d'environnement avant de créer le projet.
</Callout>

### fnOS

[fnOS](https://www.fnnas.com) embarque un panneau Docker intégré :

1. Ouvrez l'application **Docker** depuis le bureau fnOS
2. Dans la barre latérale gauche, sélectionnez **Compose** → **Nouveau projet**
3. Nom du projet : `opentickly`, laissez le chemin de stockage par défaut
4. Dans **Contenu Compose**, collez le [fichier compose](https://raw.githubusercontent.com/CorrectRoadH/OpenTickly/main/docker-compose.yml)
5. Cliquez sur **Déployer** et attendez que les trois conteneurs passent au vert

### Autres plateformes

Les plateformes suivantes suivent la même procédure Docker Compose :

- **Unraid** — via Community Applications ou le plugin Compose Manager
- **TrueNAS SCALE** — via une app personnalisée avec Docker Compose
- **Proxmox LXC** — installez Docker dans un conteneur LXC, puis suivez les étapes de la section [Déployer le serveur](#déployer-le-serveur)

## Référence de configuration

Vous pouvez modifier trois réglages via `.env` :

| Variable                      | Par défaut  | Description                                     |
| ----------------------------- | ----------- | ----------------------------------------------- |
| `OPENTOGGL_PORT`              | `8080`      | Port de l'interface web et de l'API             |
| `OPENTOGGL_POSTGRES_PASSWORD` | `postgres`  | Mot de passe Postgres (à changer en production) |
| `OPENTOGGL_REDIS_PASSWORD`    | `opentoggl` | Mot de passe Redis (à changer en production)    |

Tout le reste (nom de la base, utilisateur, tags d'image, chaînes de connexion, noms de volumes) est défini directement dans `docker-compose.yml`. Pour le changer, modifiez le fichier.

### Endpoints de vérification de santé

| Chemin     | Usage                                       |
| ---------- | ------------------------------------------- |
| `/readyz`  | Prêt à répondre ? (vérifie la base + Redis) |
| `/healthz` | Le processus tourne-t-il ?                  |
