---
title: "Sauvegardes et mises à jour"
description: "Sauvegardez PostgreSQL et testez la restauration avant de mettre à jour."
---

PostgreSQL contient les données, les fichiers téléversés et les archives d'import. Compose utilise la base `opentoggl`, l'utilisateur `postgres`, le service `postgres` et le volume `opentoggl-postgres-data-pg19`. La persistance de Redis est désactivée : rien à sauvegarder de ce côté.

## Sauvegarder

Depuis le dossier de `docker-compose.yml`, lancez :

```bash
docker compose exec -T postgres pg_dump -U postgres -d opentoggl -Fc > backup.dump
```

Gardez une copie hors du serveur. Conservez aussi `docker-compose.yml`, `.env` et la configuration du proxy en lieu sûr : ils ne sont pas dans la sauvegarde de la base.

Pour une sauvegarde quotidienne, créez `/srv/backups`, adaptez les chemins et ajoutez cette ligne au crontab d'un utilisateur ayant accès à Docker :

```text
0 2 * * * cd /srv/opentickly && umask 077 && /usr/bin/docker compose exec -T postgres pg_dump -U postgres -d opentoggl -Fc > /srv/backups/opentickly-$(date +\%F).dump
```

Vérifiez que la tâche se termine sans erreur et testez régulièrement la restauration. La présence d'un fichier ne suffit pas.

## Restaurer

Testez d'abord sur une instance séparée. La restauration remplace les objets sauvegardés et efface leurs modifications ultérieures. Utilisez la version de l'application correspondant à la sauvegarde, avec PostgreSQL démarré :

```bash
docker compose stop opentoggl &&
  docker compose exec -T postgres pg_restore -U postgres -d opentoggl --clean --if-exists --exit-on-error < backup.dump &&
  docker compose up -d opentoggl
```

Si `pg_restore` échoue, laissez l'application arrêtée jusqu'à résolution de l'erreur. Ensuite, connectez-vous et vérifiez les saisies et les fichiers. Ne supprimez pas le volume de la base.

## Mettre à jour ou revenir en arrière

Si votre fichier Compose utilise `postgres:17-alpine`, suivez d’abord les étapes de mise à niveau de PostgreSQL ci-dessous.

1. Faites une sauvegarde et notez la version ou le digest de l'image actuelle. `latest` peut changer.
2. Lancez :

```bash
docker compose pull && docker compose up -d
```

3. Le serveur met automatiquement à jour la structure de la base au démarrage. Consultez `docker compose logs opentoggl`, connectez-vous et vérifiez les données.

Pour revenir en arrière, arrêtez `opentoggl`, fixez l'ancienne étiquette ou le digest dans `docker-compose.yml`, téléchargez cette image et restaurez la sauvegarde faite avant la mise à jour. Ne lancez pas simplement l'ancienne image sur la base mise à jour. Les changements depuis la sauvegarde seront perdus.

## Passer de PostgreSQL 17 à 19 avec Docker Compose

Avant de remplacer le fichier Compose de PostgreSQL 17, enregistrez-en une copie sous `docker-compose.pg17.yml` et faites une sauvegarde. Conservez le nom du projet Compose et le mot de passe. Le nouveau volume doit disposer d’un espace libre d’au moins 1,2 fois la taille de l’ancien cluster. La première mise à niveau nécessite aussi un accès aux dépôts de paquets Alpine.

Remplacez `docker-compose.yml` par la nouvelle version, puis exécutez `docker compose up -d`. Le service `postgres-upgrade` copie le cluster vers le nouveau volume avant le démarrage de PostgreSQL et d’OpenTickly. Les installations neuves et celles déjà mises à niveau passent cette étape. Connectez-vous et vérifiez vos entrées de temps et vos fichiers téléversés.

Si le démarrage échoue, consultez l’erreur avec `docker compose logs postgres-upgrade`. Corrigez le problème et relancez `docker compose up -d`. Pour une migration manuelle, démarrez l’ancien environnement Compose et utilisez la commande de sauvegarde ci-dessus. Arrêtez l’ancien environnement, puis exécutez les commandes suivantes avec le nouveau fichier Compose et un volume PostgreSQL 19 vide.

```sh
docker compose up -d --no-deps --wait postgres &&
  docker compose exec -T postgres pg_restore -U postgres -d opentoggl --single-transaction < backup.dump &&
  docker compose up -d
```

Pour revenir en arrière, exécutez `docker compose -f docker-compose.pg17.yml up -d --remove-orphans` depuis le même répertoire. L’ancien volume conserve les données antérieures à la mise à niveau. Les écritures effectuées sous PostgreSQL 19 restent dans le nouveau volume.

Après avoir vérifié et sauvegardé la nouvelle instance, vous pouvez libérer de l’espace. Supprimez le conteneur de mise à niveau terminé, puis l’ancien volume. Si vous utilisez un nom de projet personnalisé, remplacez `opentoggl-self-hosted` par ce nom. La suppression de l’ancien volume efface la copie locale de retour en arrière.

```sh
docker compose rm -f postgres-upgrade &&
  docker volume rm opentoggl-self-hosted_opentoggl-postgres-data
```
