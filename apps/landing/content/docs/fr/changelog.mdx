Les notes de version sont sur GitHub Releases. Cette page explique comment sortent les versions et comment mettre à jour.

- Versions récentes et anciennes : [github.com/CorrectRoadH/OpenTickly/releases](https://github.com/CorrectRoadH/OpenTickly/releases)
- Historique complet des commits : [github.com/CorrectRoadH/OpenTickly/commits/main](https://github.com/CorrectRoadH/OpenTickly/commits/main)
- Images Docker : [hub.docker.com/r/correctroad/opentickly](https://hub.docker.com/r/correctroad/opentickly)

## Comment sortent les versions

Chaque version est un tag git sur `main`. Poser le tag publie automatiquement une nouvelle image Docker et met à jour la démo sur [track.opentoggl.com](https://track.opentoggl.com). Pour mettre à jour une instance auto-hébergée, lancez `docker compose pull && docker compose up -d`.

## Notes de mise à jour

En général, il suffit de mettre à jour, sans rien faire d'autre. La base de données est mise à jour automatiquement au démarrage du serveur, et l'API compatible Toggl ne change pas : vos intégrations continuent de fonctionner.

Si une version demande des étapes en plus, sa GitHub Release contient une section **Upgrade** qui les explique. Pas de section, pas d'étape en plus : c'est une mise à jour normale.

Si une mise à jour échoue, [ouvrez une issue](https://github.com/CorrectRoadH/OpenTickly/issues) avec la version, l'étape qui a échoué et le log complet.

## Rester compatible avec Toggl

OpenTickly suit les API publiques de Toggl : Track v9, Reports v3 et Webhooks v1. Les CLI, outils MCP et intégrations qui fonctionnent avec Toggl devraient continuer à fonctionner après chaque mise à jour. Quand Toggl ajoute ou modifie un endpoint, on essaie de suivre dès la version suivante.
